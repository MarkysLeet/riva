# Техническая спецификация проекта: Riva (Booking Engine, Marketplace & CRM)

## 1. Описание проекта (Project Overview)
**Riva** — это B2B2C SaaS-платформа и маркетплейс для бьюти-индустрии. Проект строится по модели SaaS-enabled marketplace: салоны и соло-мастера приходят за удобной CRM и системой онлайн-записи (защита от неявок через депозиты), а пользователи получают агрегатор для удобного поиска и букинга.

**Форм-фактор:** Mobile-first PWA (Progressive Web App).
**Дизайн-код:** Минимализм, премиальность (светлые пастельные тона), отсутствие визуального шума.
**Ключевая киллер-фича:** Жесткая привязка бронирования к холдированию средств (депозиту) для ликвидации кассовых разрывов бизнеса.

---

## 2. Пользовательские роли (User Roles)

### 2.1. Владелец бизнеса / Мастер (Business Owner)
*   **Аутентификация:** Без паролей. Только Magic Link (на email).
*   **Роутинг:** Каждый салон получает кастомный URL (например, `riva.com/avenue`). Админка доступна по адресу `riva.com/avenue/admin`.
*   **Функционал:**
    *   Настройка профиля, расписания, услуг (тайминг, прайс, размер депозита).
    *   Выбор режима модерации бронирований (Автоматический / Ручной).
    *   CRM: Календарь (drag-and-drop записей), карточки клиентов (LTV, история, индекс отмен, скрытые заметки).
    *   Аналитика и дашборд отзывов (скрытых от публики).

### 2.2. Клиент (User)
*   **Точка входа:** Прямая ссылка из Instagram салона ИЛИ главная страница-агрегатор (`riva.com`).
*   **Флоу записи (Checkout Funnel):**
    1.  Выбор услуги и мастера.
    2.  Выбор времени (календарь рендерит только слоты, куда помещается длительность услуги + буферное время).
    3.  Ввод контактов (Имя, телефон). Авторизация по номеру телефона (OTP/СМС) для связи с профилем в CRM.
    4.  Оплата депозита (Apple Pay / Google Pay / Card).

## 3. Критическая бизнес-логика (Core Logic & State Machines)

### 3.1. Механика "Временной блокировки слота" (Concurrency Control)
При переходе клиента на Шаг 4 (Оплата) система **должна временно заблокировать слот на 10 минут**.
*   *Таймер истек, оплаты нет:* Слот автоматически освобождается (возвращается в availability pool).
*   *Оплата прошла:* Переход к созданию бронирования (Booking State Machine).

### 3.2. Статусы бронирования и платежей (Booking State Machine)
Движок должен поддерживать связку "Статус заявки" + "Статус транзакции (Acquiring)".

| Статус брони | Статус платежа (Депозит) | Условие / Триггер | Действие системы |
| :--- | :--- | :--- | :--- |
| `PENDING_APPROVAL` | `AUTHORIZED` (Hold) | Клиент оплатил, но у салона стоит "Ручной аппрув". | Пуш мастеру. Слот занят. Деньги заморожены, но не списаны. |
| `CONFIRMED` | `CAPTURED` (Charged) | Мастер нажал "Подтвердить" (или стоит "Авто-аппрув"). | Пуш/СМС клиенту. Запись в CRM. Списание денег с карты. |
| `CANCELED` | `VOIDED` / `REFUNDED` | Мастер отклонил заявку ИЛИ клиент отменил по правилам. | Слот освобождается. Холд снимается (или возврат). |
| `NO_SHOW` | `CAPTURED` (Penalty) | Клиент не пришел / отменил слишком поздно. | Депозит уходит мастеру как штраф. Метка в профиль клиента. |

## 4. Архитектура баз данных (High-Level Entities)

*   **Tenant (Салон/Бизнес):** id, slug (для URL), name, settings (глобальная скидка, режим модерации, правила отмены), subscription_status, referral_id.
*   **Master (Сотрудник):** id, tenant_id, name, schedule_rules (рабочие часы, перерывы).
*   **Service (Услуга):** id, tenant_id, name, duration_minutes, buffer_minutes, price, deposit_amount_or_percentage.
*   **Master_Service (M2M):** Связка, какие мастера делают какие услуги.
*   **Client (Пользователь):** id, phone, name.
*   **Client_Profile (CRM-карточка):** id, client_id, tenant_id, ltv, strike_count (отмены), internal_notes (скрытые заметки).
*   **Booking (Рандеву):** id, tenant_id, master_id, client_id, service_ids (array), start_time, end_time, status, payment_intent_id.

## 5. Дополнительные фичи (Roadmap & Edge Cases)

1.  **Реферальная система:**
    *   Отслеживание `referrer_id` при регистрации нового салона.
    *   Начисление 10% от стоимости подписки (Recurring payout) рефоводу.
2.  **Апсейл и доплата наличными:**
    *   Возможность мастеру при завершении визита изменить итоговую сумму чека (добавили дизайн ногтей, купили крем). Депозит вычитается, остаток фиксируется как "оплачено наличными/терминалом" для корректного подсчета LTV.
3.  **Черный список:**
    *   Таблица блокировок (по номеру телефона на уровне Tenant). При попытке записи выдается заглушка-ошибка на фронтенде.

## 6. Технологический стек (Рекомендации)
*   **Frontend:** React / Next.js (для SEO агрегатора и PWA). Tailwind CSS для UI.
*   **Backend:** Node.js / NestJS или Supabase/Firebase для быстрого старта.
*   **Payments:** Stripe (поддержка Auth & Capture, сплитование платежей для рефералок и комиссий).
*   **Database:** PostgreSQL (строгая реляционная структура для CRM и консистентности транзакций).
